# video-production

> 用代码生成视频（动效片 / 数据动画 / 解释片 / 循环动画 / 生成艺术）的**作业规范 ＋ 可直接运行的验收脚本**。
> 一篇 `SKILL.md` 讲清顺序与判据，两个零依赖脚本把判据变成可执行断言。

## 这个技能是干什么的

程序化出片的失败模式几乎全是**单位/符号/通道/指标**级的隐蔽错误：整片暗 30%（画布 alpha 累加）、字幕被裁一半（复用画布尺寸按逻辑内容而非源画布分配）、居中对齐失效（mask 居中而 `strokeText` 左对齐）、循环接缝对不上、响度差 1 LU、某段 1.2 秒完全静止——**它们都能静默交付**。

这个技能把这类任务固定成三段结构，让每个错误都变得"看得见"：

1. **契约**：一切都住在纯函数 `render(t)` 里（无定时器、无帧间状态、种子化随机、资产内嵌），帧号↔时间是唯一 API。于是可并行、可跳帧重渲、可对比任意两帧、可把 bug 定位到时间段。
2. **探针**：开工第一天就要有三支廉价探针——帧完整性（尺寸/**alpha=255**/色彩范围）、单帧成本、全片运动曲线与最长静止段。
3. **判据**：简报里的每个数字都落到一条断言；脚本逐条打印 `PASS/FAIL`、输出 JSON、以退出码收尾。

同时给出十类**已知会翻车的地方**和对应做法：白底合成陷阱、指标敏感性（下采样均差看不见细线亚像素运动）、先验指标再改资产、检测器偏置要显式补偿、循环代数（所有振荡周期整除时长并收敛回初态）、环境通道≠动作频率、按耗时而非帧数并行、段间重复边界帧＋`-c copy`、两遍 loudnorm＋第三遍独立复测、`-b:a` 是目标不是下限。

## 什么时候会被加载

任务命中下列任一情形时，AI 应在写第一行绘制代码前加载它：交付物是 mp4/webm/gif；做动效片、数据动画、解释片、循环动画、音频响应式画面；要把帧序列与音频混流；要验证时长/帧率/容器规格、循环无缝、冻结帧下限、接触表评审、响度与真峰、渲染吞吐。

**不适用**：只做一张静帧；直接剪素材而不用代码生成帧；纯三维 DCC（Blender 等）出片。

## 正文覆盖的 10 个环节

| 节 | 要点 |
|---|---|
| 0 冻结契约 | 单一时间源、确定性、规格转断言、**接缝策略与循环代数**、每帧预算、冻结接口并记 hash、有意偏离登记 |
| 1 三支探针 | 帧完整性/成本/运动；白底合成陷阱；**先量化指标敏感性**；先验指标再改资产；检测器偏置显式化；精确 vs 近似断言 |
| 2 评审循环 | 网格化接触表、烧入安全框与时间码、按事件采样、紧盯接缝、隔离放大、评审件可弃可再生 |
| 3 动效与循环 | 环境通道≠动作频率且零点对齐事件、单一缓动家族且事件处落定、帧内运行平均模糊＋索引夹具证明滤镜窗口、同几何变形转场、长度守恒形变 |
| 4 渲染与编码 | 格式 vs 吞吐先量后定、管道不落盘、**按耗时并行**、段间重复边界帧、阶段化可恢复、无损母版、探测未知工具链、**沙箱下用文件描述符而非管道捕获子进程** |
| 5 音频与混流 | 同一时间基准、cue 表唯一事实源、两遍 loudnorm＋第三遍复测、循环尾 40 ms 归零、容器断言 |
| 6 绘制层性能 | 缓存键含全部影响像素的参数、画布池按**源画布**尺寸、避开 shadow/filter、内存上限 |
| 7 协作 | 作者/验证者分离、写入范围互斥、失败要响 |
| 8 反模式 | 10 条具体反模式清单 |
| 9 清单 | 开工前 / 制作中 / 交付前 / 完成定义（DoD） |
| 10 脚本 | 两个脚本的用法与退出码约定 |

## 内置脚本

零依赖，只需 `ffmpeg`/`ffprobe`（按 `$FFMPEG`/`$FFPROBE` → PATH → 常见安装位置解析）。逐条 `PASS/FAIL`，`--json` 输出机器可读结果，失败非零退出。

```bash
# 验收成品：容器与期望值、最长静止段、首末帧接缝、响度/真峰，可选接触表
node av_audit.mjs film.mp4 --expect-duration 30 --expect-fps 60 --expect-size 1920x1080 \
     --static-limit 0.5 --sheets ./sheets        # exit 0 = 全部通过

# 把 WAV 归一化到目标响度并混流到已编码视频（视频流 -c:v copy），再做第三遍独立复测
node mux_normalize.mjs silent.mp4 score.wav film.mp4 --lufs -14 --tp -1 --abr 320k
```

`av_audit.mjs` 的运动检测刻意用 160×90 下采样均差：它看得见整幅明暗变化与块移动，**看不见细线的亚像素运动**——所以配一条"全局价值通道"（如与节拍同频的 ±3% 亮度脉动）才能真正满足"任何时候都不静止"。

## 为什么可信：来自真实项目的实测

沉淀自一次真实交付（30 秒 1920×1080 60fps 无缝循环片，5400 子帧、10 进程并行、H.264 CRF 14、AAC）：

| 指标 | 实测 |
|---|---|
| 时长/帧数/帧率 | 30.000 s / 1800 帧 / 60 fps，容器精确 |
| 循环 | 渲染器 `t=0` vs `t=30`：PSNR ∞、MAD 0（精确同一帧） |
| 最长静止段 | 0.183 s（限值 0.5 s）；中位帧间差 0.98/255 |
| 响度 / 真峰 | −14.00 LUFS / −1.58 dBTP（两遍归一化＋第三遍复测） |
| 打击点对齐 | 60/60 命中，均值 2.4 ms、最大 9.5 ms |

写作过程中真实踩到并写进技能的坑还包括：画布 alpha 半透明导致整片变暗（且只在深色合成下可见）、复用画布尺寸按逻辑内容分配导致字形被裁、`strokeText` 忽略对齐导致 750 px 重影、按帧数均匀并行让最慢的 worker 决定总时长、把检测器问题误当资产问题——这些都已固化成对应章节。

## 安装

```bash
git clone https://github.com/daoge96/dsh-skills
cp -r dsh-skills/video-production ~/.dsh/skills/                 # 用户级，对所有工作区生效
cp -r dsh-skills/video-production <项目>/.dsh/skills/            # 或项目级
```

DSH 会监听技能目录，复制后无需重启即可被 AI 发现。
